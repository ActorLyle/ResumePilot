# 简历专家｜本地版

简历专家是一个在个人电脑上运行的职位匹配与简历优化工具。它将目标岗位 JD 与真实简历进行分析，帮助用户发现岗位要求、简历证据和能力缺口，并准备定制化的简历建议及面试材料。模型通过用户自行配置的火山引擎方舟 API 调用。

## 解决什么问题

通用简历不容易针对不同职位突出相关经验，求职者也难以判断 JD 中的要求是否已由简历提供证据。本工具把岗位要求与候选人的实际经历逐项对照，给出需要核实、补充或改写的内容。模型提示要求避免编造，但使用者仍须核实所有事实、职责和数字；本工具不保证录用结果。

## 主要功能

分析完成后，左侧按八个步骤展示结果：

1. 输入岗位信息、JD、简历正文和可选补充信息。
2. 解析 JD 中的职责、硬性/软性要求、关键词和核心能力。
3. 评估简历与目标岗位的匹配度，列出问题和改进建议。
4. 逐项对照岗位要求与简历证据，指出缺口。
5. 生成经历追问，帮助补齐项目细节。
6. 对照展示简历修改前后内容，可切换默认、简洁、降低夸张、偏 AI 产品、偏 ToB SaaS 等表达风格。
7. 汇总最终简历，可复制到剪贴板。
8. 准备面试问题、所需证据和自我介绍建议。

也支持示例材料填充，以及 `.docx` 和带文字层的 `.pdf` 文件解析（单文件不超过 10 MB）。

### 当前版本说明

- 简历文件在本机内存中解析，不保存原文件；提取出的简历正文、JD 和补充信息会发送给方舟模型。扫描版 PDF 需要先 OCR，或直接粘贴文字。
- “复制到剪贴板”不会生成 Word 或 PDF 文件。
- “经历追问”里的“生成简历表达”目前使用内置示例文案，不会根据回答实时调用模型；请核实并自行编辑。
- 右下角 AI 助手入口目前不是完整的聊天功能。
- “示例数据”仅填入演示材料；点击“开始分析”仍会调用用户配置的真实 API，不会在调用失败时静默切换到 Mock 结果。

## 安装与启动

### 准备环境

- Windows 或 macOS
- Node.js `20.16+`（20.x）或 `22.3+`
- 可访问 npm registry 的网络（首次启动且目录中没有 `node_modules` 时需要安装依赖）

### 下载并启动

1. 下载项目 ZIP 并解压到本机目录。
2. Windows 用户双击 `start.bat`；macOS 用户双击 `start.command`。脚本会切换到自身所在目录；若没有 `node_modules`，先运行 `npm install`，然后运行 `npm start`。
3. 脚本启动本地代理和网页服务，并打开默认浏览器访问 `http://localhost:3000`。
4. 页面右上角点击“API 配置”，输入自己的 `ARK_API_KEY` 和火山方舟 `Endpoint ID`，点击“保存并使用”。
5. 填写 JD 和简历正文，点击“开始分析”。

macOS 如果提示脚本没有执行权限，在终端进入解压目录后运行一次 `chmod +x start.command`，再双击该文件。也可以在项目目录手动启动：`npm install`（首次）后执行 `npm start`，然后访问 `http://localhost:3000`。

启动端口固定为网页 `3000`、本地代理 `3002`。如果端口已被占用，关闭占用它的程序后重新启动。关闭启动脚本打开的终端窗口或按 `Ctrl+C` 可停止服务。

## API 配置与密钥传递

不需要创建或修改 `.env` 文件。API Key 与 Endpoint ID 由用户在网页的“API 配置”弹窗中输入并保存到当前浏览器的 `localStorage`；项目源码不包含用户密钥或用户的 Endpoint ID。API Key 保存在本机浏览器配置中，不是加密保险库；同一浏览器配置下的脚本可读取它，请妥善保管个人电脑，不要在不可信页面运行本工具。

调用链路如下：

```text
配置弹窗 → 浏览器 localStorage → POST /api/chat
  x-ark-api-key、x-ark-endpoint 请求头
  → 本地 Express 代理 → Authorization: Bearer <用户的 API Key>
  → 火山方舟 Chat Completions API
```

Endpoint ID 会作为上游请求的 `model` 字段发送。浏览器只向本机 Vite 地址请求 `/api/chat`；Vite 再把请求转给本机代理，避免浏览器直接跨域访问方舟。代理不会把收到的 API Key 写入日志。

打包或分享 ZIP 时请勿包含个人的 `.env`、浏览器数据或其他密钥文件；本工具不会读取 `.env`，最终用户应在界面中输入自己的 Key 和 Endpoint ID。遗留的 `.env` 文件不会被启动流程加载。

## 输入与输出示例

### 示例输入

```text
目标岗位：AI 产品经理

目标岗位 JD：
负责企业 AI 产品规划和需求分析；协同研发、算法团队推动产品上线；
基于用户反馈和业务数据持续迭代。要求有 B 端产品经验、数据分析能力并了解大语言模型。

原始简历：
负责 ERP 系统需求分析和功能设计；参与 WMS 模块迭代；设计经营数据报表，
报表产出效率提升约 40%。

补充信息（可选）：
希望转向 AI 产品方向；报表效率数据可以提供记录核实。
```

### 示例输出

实际评分和措辞取决于用户材料及模型返回，以下仅为页面结果的简化示意：

```text
JD 解析：B 端产品规划、跨团队协作、数据分析、LLM 认知
简历诊断：综合匹配度（模型评估）；指出 AI 项目证据不足等缺口
匹配分析：
  要求：数据分析能力
  证据：经营数据报表；简历提到产出效率提升约 40%
  建议：确认统计口径、基准和影响范围后再保留该数字
经历追问：报表覆盖哪些指标？效率提升是如何计算的？
简历优化：对照展示原文和建议表达，并提供不同风格版本
面试准备：围绕 AI 转型动机、数据成果和项目细节准备证据
```

## 本地验证与排错

服务启动后，可在浏览器开发者工具 Console 查看本地代理是否正常：

```js
fetch('/api/health').then(r => r.json()).then(console.log)
```

正常时应返回 `ok: true`。调用模型时，Network 面板中的 `POST /api/chat` 应返回方舟响应；浏览器请求头中能看到发往本机代理的 `x-ark-api-key` 和 `x-ark-endpoint`，这是本地版设计的一部分。API Key 不应出现在 URL、页面源码或代理日志中。

- `ARK_API_KEY_REQUIRED`：在“API 配置”中填写并保存 API Key。
- `ENDPOINT_REQUIRED`：在“API 配置”中填写并保存 Endpoint ID。
- `UPSTREAM_TIMEOUT`：检查网络或稍后重试；代理对一次请求至少等待 5 分钟。
- `PROXY_ERROR` / 502：查看启动终端中的 DNS、连接拒绝、权限或 TLS 诊断信息。
- 文件解析失败：确认文件未加密或损坏、大小未超过 10 MB；扫描版 PDF 请 OCR 后粘贴文字。
- 浏览器无法连接：确认启动终端里的服务仍运行，并访问 `http://localhost:3000`。
